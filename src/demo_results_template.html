01

Does the layering pay off?

All three layers rank the same candidate pool, so every difference reflects ordering quality alone. Significance is by paired bootstrap over 2,000 resamples, with sessions resampled together to preserve the correlation between layers.

02

Why Layer 2 needed a residual connection

The knowledge graph is roughly 90% of a complete bipartite graph, because the rule engine needs a weight for every context–intervention pair. At that density, repeated neighbourhood averaging drives every intervention representation together and ranking becomes impossible.

Diagnosed, not assumed

This is the oversmoothing effect described by Li, Han and Wu (AAAI 2018), and it arose here from graph topology rather than an implementation error. Adding a residual path lifted cross-validated AUC from 0.653 to 0.730.

A validation-size lesson

An earlier version used a single holdout rather than cross-validation. The same architecture measured 0.424 AUC on the holdout and 0.653 under cross-validation — acting on the first would have discarded a working model. Every selection decision in Module 3 uses cross-validation as a result.

The edge structure adds +0.011 AUC — inside one standard deviation

Every edge weight in the graph is a deterministic function of node attributes that are already present in the node feature vector, so message passing has nothing new to propagate. Layer 2's improvement is real and statistically significant, but it comes from learned attribute weighting rather than graph-structural learning. This corrects a claim made in our interim report, and it is reported as measured rather than oversold.

04

Layer 3, and why conventional metrics could not be used

Precision@K and NDCG@K define relevance from each user's own training ratings — the same source Layer 3 personalises from — which makes them circular. A ranker with no model at all, sorting the pool by that quantity, scores 0.9702 on Precision@3 against Layer 2's 0.5952. Layer 3 is therefore evaluated off-policy instead.

No sub-layer is statistically distinguishable from Layer 2.

05

Why personalisation shows no gain — measured

Rather than reporting the null and stopping, we regenerated the dataset across a grid of individual preference strengths and sessions per user, and measured where personalisation becomes recoverable at all.

The constraint is effect size, not data volume

Recovery requires a preference strength of 1.2 or above — roughly double what this dataset contains — and that threshold is essentially flat from 28 to 224 sessions per user. Increasing sessions eightfold does not bring the observed effect into range.

Validated in both regimes

A null result alone cannot separate "no signal" from "broken implementation", so every component was tested both ways. The personalisation network collapses to R² 0.0041 on real data and recovers R² 0.9313 on data containing a planted effect of known size — same code, same folds.

06

Safety and feasibility

100% compliance within available context

Across every evaluated session, the module never proposed an intervention the user could not perform — against 79.5% for a content-based baseline with no feasibility filtering. Constraints are enforced structurally: an excluded intervention never enters the candidate pool, so no scoring error can surface one.

What missing context costs

Measured against the true recorded context, compliance is 96.4%. The entire gap comes from sessions where no contextual dialogue occurred: zero violations across the 96 sessions with a completed dialogue, and five across the 16 without — a direct measure of what Module 2 contributes to the pipeline.
